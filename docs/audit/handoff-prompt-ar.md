# برومبت التسليم — من جلسة الكلاود إلى الجهاز المحلي

انسخ النص التالي كما هو والصقه في Claude Code على جهازك داخل مجلد المشروع.

---

أنت الآن تعمل على جهازي المحلي داخل مشروع CAUSASEAL. قبلك كانت جلسة Claude Code على **سيرفر سحابي** (بيئة معزولة بلا Cursor، والشبكة فيها كانت تحجب `api.cursor.com`). الجلسة السحابية أوقفناها عمدًا لتوفير التوكنز، وكل شغلها مرفوع على GitHub. مهمتك أن تكمل من حيث توقفت، **بدون إعادة الفحص من الصفر**.

## ما الذي حصل في جلسة الكلاود

1. أُضيف `CLAUDE.md` (يستورد `AGENTS.md` ويشرح المعمارية والأوامر).
2. أُخذ خط أساس على `main` @ `9f05d44` (الإصدار 0.10.10):
   - `npm test`: النتيجة 27/27 ناجح.
   - `npx tsc --noEmit`: نظيف.
   - `npm run lint`: خطآن `react-hooks/set-state-in-effect`، في `components/causaseal/connectors-http-view.tsx:63` و`connectors-mcp-view.tsx:39`.
   - `npm run build`: ناجح.
   - `npm audit`: 27 ثغرة، منها واحدة حرجة في `next` 16.3.4 (المطلوب ≥ 16.3.8)، ومعظم الثغرات العالية جاية من scaffold ميت (vinext/Cloudflare/Drizzle).
3. شُغّل تدقيق متعدد الوكلاء: 12 عدسة من أصل 38 اكتملت، والباقي أُوقف. كل وكيل **شغّل الكود فعلًا** (سكربتات node، و`curl` على `server.js`، وعميل MCP حقيقي) ولم يكتفِ بالقراءة.
4. الناتج 149 ملاحظة **خام غير مُتحقَّق منها**: 2 حرجة، 18 عالية، 75 متوسطة، 54 منخفضة.
5. وُزّعت الملاحظات على 7 مسارات عمل، مع ترتيب دمج وتقسيم للملفات يقلّل التعارض.

## الملفات (على الفرع `claude/ecstatic-gauss-4kq2wx`)

## المطلوب منك بالترتيب

1. **جهّز المشروع محليًا:**
   ```bash
   git fetch origin
   git checkout claude/ecstatic-gauss-4kq2wx
   npm ci
   npm test && npx tsc --noEmit && npm run lint
   ```
   تأكد أن النتائج تطابق خط الأساس أعلاه. لا تعِد التدقيق.
2. **ثبّت مهارة Cursor Delegate في المشروع.** إذا ما عرفت مصدرها، اسألني عن الرابط قبل أن تخمّن.
3. **اقرأ `docs/audit/cursor-delegation.md` كاملًا**، وفوّض عبر Cursor Delegate **7 وكلاء فقط**، وكيلًا لكل مسار (WS1 إلى WS7):
   - أعطِ كل وكيل قسم مساره من الملف كما هو، مع قسم «القواعد لكل وكيل».
   - **النموذج:** WS1–WS4 (أمان المدخلات، ومحرّك القرار، والذاكرة والحالة، وMCP و SDK) تحتاج تفكيرًا عميقًا، فاستخدم **Grok 4.7 High**. أما WS5–WS7 (التبعيات والـ scaffold، ومنطق الواجهة، والترجمة وإمكانية الوصول) فاستخدم **auto** أو **Composer**.
   - **التوازي:** شغّل WS1 و WS2 و WS5 أولًا. بعدها شغّل WS3 (يعتمد على WS2 في `engine/gateway.mjs`)، وWS4 (يعتمد على WS1 في `server.js`)، ثم WS6 وبعده WS7.
4. **قواعد غير قابلة للتفاوض** تمرّرها لكل وكيل:
   - لكل إصلاح فرعٌ من `main` وPR مستقل بالإنجليزية بتقرير مفصّل.
   - **ممنوع الدمج** وممنوع الدفع إلى `main` وممنوع force-push. الدمج قراري أنا.
   - كل ملاحظة تُعاد إنتاجها على `main` قبل إصلاحها، وإن لم تتكرر تُترك ويُذكر ذلك في الـ PR.
   - لا يُلمس `CHANGELOG.md` ولا رقم الإصدار في `package.json` ولا كتلة `nextjs-agent-rules` في `AGENTS.md`.
   - `MATCH_THRESHOLD = 0.6` يبقى كما هو.
   - `/mcp` يبقى بلا مصادقة.
   - أسماء الأدوات تبقى `causaseal_*`، والواجهة تبقى ثنائية اللغة.
   - حالات اللجنة الأربع في `/architecture` يجب أن تبقى نتائجها كما هي.
   - قبل كل push يجب أن ينجح `npm test` و`npx tsc --noEmit` و`npm run lint`، ويُضاف `npm run build` إذا لُمست الواجهة أو الإعدادات أو `package.json`.
5. **تابع الوكلاء ولا تنفّذ عملهم بنفسك.** دورك تنسيق ومراجعة فقط.
6. **عند الانتهاء**، أعطني تقريرًا بالعربية يحتوي:
   - جدول الـ PRs (الرقم، والمسار، والملاحظات التي أصلحها، وحالة الفحوصات).
   - الملاحظات التي تُركت وسبب تركها.
   - ترتيب الدمج المقترح.
   - مقارنة قبل/بعد: الاختبارات، والـ lint، و`npm audit`.

**ابدأ بالخطوة 1 وأخبرني بالنتيجة قبل أن تفوّض.**
