# مطابقة الفكرة مع الكود

آخر تحديث: 24 سبتمبر 2026.  
مصدر الفكرة الأساسية (لا يُعدَّل هنا): [`docs/فكرة-CAUSASEAL-SERMG.md`](فكرة-CAUSASEAL-SERMG.md) — نسخة Git الأولى قبل الموصّلات: كومِت `a90dcbf`.  
نص التسجيل للصق: [`docs/نص-التسجيل.md`](نص-التسجيل.md).  
رن بوك اللجنة: [`docs/runbook-لجنة.md`](runbook-لجنة.md).

**جملة المنتج كما يعمل الكود:** نركب فوق هارنس الوكيل. الهارنس يحكم على الأداة الحالية. نحن نحفظ سبب الحادث السابق، نعرفه إذا رجع بشكل جديد، ونقطع تلك العلاقة والمهمة تكمل.

بوابة الإصدار: ممنوع إصدار ويندوز / ماك / لينكس / أندرويد / iOS إلا بموافقة صريحة.

## 1) الفكرة الأساسية — تاسكات

ما وعدته وثيقة الفكرة الأولى (قبل MCP / SDK / هب الموصّلات): ثلاث ركائز + بوابة تشغيل + أثر قابل للعرض.

### 1.1 المشكلة والفجوة — [x]

- [x] صياغة المشكلة: خطر يتكوّن عبر مسار تنفيذ الوكيل، لا عبر إجابة نصية وحدها
- [x] الفجوة: تحويل سبب الحادث إلى معرفة تمنع إعادة تشكّله بعد تغيّر الشكل

### 1.2 الابتكار (1) — التوقيع السببي المصغّر X-CFS — [x]

- [x] عقد مسار الأداة في `engine/contracts.mjs`
- [x] استخراج ثوابت شكل المسار في `engine/xcfs.mjs` (بلا قائمة كلمات `HOSTILE` وبلا أسطر وهمية)
- [x] اختزال إلى العقد الحرجة مع نسبة اختزال محسوبة على عقد المسار (ليست على تيرابايت سجلات خارجية)
- [x] قرار هيكلي: `ALLOW` / `VERIFY` / `INTERVENE` في `engine/gateway.mjs`

### 1.3 الابتكار (2) — محرك SERMG (طفرات الصياغة) — [x]

- [x] `engine/sermg.mjs`: توليد صياغات متغيرة وإعادة تشغيل البوابة
- [x] صياغة مستجدة غير مخزّنة في القوالب: `engine/fixtures/novel-leak.mjs`
- [x] مختبر SERMG في الواجهة

### 1.4 الابتكار (3) — ذاكرة عابرة للسياقات — [x]

- [x] تخزين بصمات مع ثوابت في `engine/memory.mjs`
- [x] مطابقة Jaccard بعتبة `0.6`
- [x] عزل الجهات `orgs[orgId]`
- [x] نقل التعلم عبر بيئة (مثلًا dev → enterprise) في مسار `cross`

### 1.5 بوابة التشغيل السببية (Runtime Gateway) — [x]

- [x] اعتراض قبل الأداة: `POST /api/gateway/intercept`
- [x] وكيل العمليات قبل الإرسال: `POST /api/agent/run` + `engine/ops-agent.mjs`
- [x] عند INTERVENE: نسخة محذوفة؛ الأصل لا يُرسل
- [x] عند ALLOW: إرسال الأصل إلى صندوق محلي (محاكاة)
- [x] عند VERIFY: لا إرسال حتى يراجع شخص

### 1.6 الأثر والعرض والتحقق (دعم عرض الفكرة) — [x]

- [x] صفحة `/impact` بسيناريوهات حية من الجلسة
- [x] مركز العمليات ومراقبة `/monitor` من أحداث الجلسة فقط (بلا أرقام مزروعة)
- [x] تقارير / تنزيل JSON من مقاييس الجلسة
- [x] شاشة أولى بجملة الفرق ومثال الحلقة
- [x] اختبارات المحرك: `npm test` (بوابة + ذاكرة + أثر)

### 1.7 من الفكرة الأساسية — مهيأ ولم يُوزَّع — [x] جزئي

- [x] Capacitor مهيأ في المستودع
- [ ] إصدار متاجر / حزم سطح المكتب (موقوف ببوابة الإصدار)

### 1.8 من وثيقة الفكرة — غير منفّذ كما كُتب تسويقيًا

- [ ] أرقام 90٪ / 99٪+ / 95٪ مقاسة على سجل خارجي (معلّمة «غير مقاس» في ملف الفكرة)
- [ ] متجهات رسومية كاملة ومسافات رسوم (البديل الحالي: Jaccard على ثوابت نصية)
- [ ] IAM / Entra / EHR / بريد / SIEM إنتاجي

**خلاصة الفكرة الأساسية في الكود:** بوابة شكل مسار + ذاكرة ثوابت + SERMG طفرات + منع أو نسخة محذوفة قبل الأداة — عبر اعتراض HTTP المحلي. هذا يكفي لإغلاق خطة المراحل الست أدناه.

## 3) تقدير سيف الداخلي (خطة المستودع — ليست درجة اللجنة)

هذان رقمان داخليان لإغلاق **خطتنا نحن** بدليل في المستودع.  
**لا** يعنيان أن محكّم سيف سيعطي نفس الدرجة، ولا أن المنتج جاهز للإنتاج.

| النوع | المعنى | الرقم |
| --- | --- | ---: |
| اكتمال تاسكات الفكرة الأساسية أعلاه | الدوال والصفحات الموعودة في الخطة موجودة ولها دليل | 100 / 100 داخلي |
| أوزان معايير سيف (فئة أكبر من 18) كما ربطناها نحن | بعد إغلاق المراحل الست | **100 / 100** داخلي |

| المعيار | الوزن | تقديرنا | دليل مختصر |
| --- | ---: | ---: | --- |
| الأصالة والابتكار | 25 | 25 | ثوابت شكل المسار + بصمة بدون HOSTILE؛ صياغة متغيرة تُمنع |
| الأثر والتطبيق | 25 | 25 | وكيل قبل الأداة + `/impact` + نسخة محذوفة |
| الجودة التقنية | 20 | 20 | أرقام الجلسة فقط + `npm test` |
| التحقق والإثبات | 15 | 15 | تقرير جلسة JSON + جدول حالات الاختبار |
| العرض والتواصل | 10 | 10 | شاشة أولى + جملة الفرق + ترتيب القائمة |
| الاستدامة | 5 | 5 | عزل `orgId` + فقرة التشغيل |

### خطة الوصول إلى 100 — مغلقة

| المرحلة | المعيار | من → إلى | تم |
| --- | --- | ---: | --- |
| 1. بصمة من مسار أداة | الأصالة | 16 → 25 | [x] |
| 2. وكيل قبل الأداة | الأثر | 11 → 25 | [x] |
| 3. أرقام مقاسة واختبارات | الجودة | 12 → 20 | [x] |
| 4. ملف الإثبات = الجلسة | التحقق | 6 → 15 | [x] |
| 5. أول شاشة تعلّم الحلقة | العرض | 4 → 10 | [x] |
| 6. تشغيل لكل جهة | الاستدامة | 2 → 5 | [x] |

تشغيل التحقق: `npm test`.

## 4) تنبيه سريع

| الرقم | يعني | لا يعني |
| --- | --- | --- |
| 100 داخلي | أغلقنا تاسكات الخطة في المستودع | أن اللجنة ستعطي 100 أو أن الفكرة مضمونة المركز الأول |
| ملف الفكرة | الوثيقة الأصلية للتسجيل والعرض | أن كل جملة تسويقية فيها منفّذة حرفيًا في الكود |
| الموصّلات / المعمارية / القطع المسمّى | إضافات فوق الفكرة الأساسية | أنها كانت في كومِت الفكرة الأولى |

**قاعدة أي تطوير لاحق:** هل يزيد الفرق عن هارنس الوكيل بطريقة يعيدها المحكّم بنفسه، أم يزيّن الشاشات فقط؟
